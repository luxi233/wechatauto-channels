# Agent Note: Hermes 插件实弹接入暴露的三个缺陷（v0.1.1 修复）

Status: implemented

## Problem

v0.1.0 在真实 Hermes 0.21.0 实例（微信 4.x 在线）上接入时暴露三个缺陷：

1. **`hermes/wechatauto/__init__.py` 不导出 `register`**：Hermes PluginManager
   在包级探测 `register()`，只把它放在 `adapter.py` 会导致
   `has no register() function`、插件被跳过。bundled 插件的惯例是
   `__init__.py` re-export。
2. **发送结果恒为失败**：`core.send_text`/`send_file` 用
   `resp["status"].lower() == "success"` 判定，而
   `wechatauto-replica` 的 `WxResponse.status` 实际返回中文
   `成功/失败/错误`。每次物理发送成功却回报 `ok: False`，Hermes 的
   `_send_with_retry` 判定非网络失败后走 plain-text fallback 重发——
   用户看到每条回复都重复一遍，第二遍带
   `(Response formatting failed, plain text:)` 前缀。
3. **adapter 按上游 main 编写，0.21.0 缺整套 API**：
   `gateway.platforms.access_policy_mixin`、`platforms.event`、
   `_shared` 里的 `extra_or_secret`/`seed_extra_from_env`/
   `apply_yaml_bridge`/`send_error` 四个 helper、
   `MessageEvent.reply_expected` 字段在 0.21.0 全部不存在，
   插件裸装直接 ImportError/TypeError。

另有一个上游缺陷不属于本仓库但在此记录：
`wechatauto-replica` 的 `wechatauto/logger.py` 在模块级实例化
`wxlog` 时执行 `root_logger.handlers.clear()`，任何
`import wechatauto.*` 都会拔掉宿主进程的日志管线——Hermes gateway
日志在插件 `connect()` 调用 `core.start()` 那一刻全体静默。

## Decision

- `__init__.py` 改为 `from .adapter import register` + `__all__`。
- `send_text`/`send_file` 的 `ok` 判定改为
  `str(resp.get("status", "")) in ("成功", "success")`。
- adapter 对缺失 API 一律 try/except 双兼容：优先用宿主的
  `_shared`/`access_policy_mixin`/`platforms.event`，ImportError 时回退
  插件内 vendored 的 `_compat_shared.py`/`_compat_policy.py`
  （仅依赖 0.21.0 已有的 `get_scoped_secret` 与 `gateway.session`）。
  `reply_expected` 改为构造后 `setattr`，避免对老签名传未知 kwarg。
- adapter 增加 `_preserve_root_logging()` 上下文管理器，包住两处
  `wechatauto` 懒导入点：快照并还原 root handlers/level。replica 上游
  修复 `logger.py` 之前，重装/升级也不会再劫持 gateway 日志。

## Alternatives considered

- **要求用户升级 Hermes 到上游 main**：放弃。接入方 pinned 在
  0.21.0 且有本地改动，渠道插件不该要求宿主升级；try/except vendor
  对上游 main 同样兼容（宿主有能力时优先用宿主的）。
- **`ok` 判定改用 `bool(resp)`/`resp.is_success`**：放弃。`WxResponse`
  的 `__bool__` 语义依赖具体版本实现，`status` 字符串比对是
  公开可观测字段，双值白名单更直白。
- **在 replica 上游修 logger 后不加防御守卫**：放弃。守卫成本极低，
  且保护的是"库在 import 时改宿主全局状态"这一类问题，
  不限于当前这个实例。

## Consequences

- 收益：Hermes 0.21.0 与上游 main 均可裸装接入；重复回复消除；
  gateway 日志管线不再被静默劫持。
- 代价：插件目录多了两个 vendored compat 文件（约百行），随上游
  Hermes 演进需要同步观察 `_shared` helper 的真实签名漂移。
- 待上游：`wechatauto-replica` 的 `logger.py` 修复需回灌包维护方，
  未合并前升级 replica 仍会触发劫持（adapter 守卫兜底）。

## Verification

- `python -m unittest discover -s tests`：34 项全过。
- Hermes 0.21.0 实弹：`gateway_state.json` 报 `wechatauto: connected`；
  py-spy 确认 `wxdb-listener`/会话 worker 线程在 gateway 进程内；
  真实入站 DM 回复发出，零 `Send failed`/`fallback` 记录。
